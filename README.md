# Keitaro Campaign Manager

Веб-обёртка над Keitaro Admin API из двух частей:

- **Создание кампании** (`/`) — название, гео, оффер с автокомплитом. Создаёт кампанию
  с доменом, группой и источником из `.env` и два потока:
  Flow 1 — фильтр «страна = гео» → редирект на `https://google.com`;
  Flow 2 — выбранный оффер (100%).
- **Редактор** (`/editor`) — потоки кампании и офферы с долями: добавление, удаление,
  возврат удалённых (bring back), закрепление доли (pin), публикация в Keitaro (Push to KT).

Стек: FastAPI, SQLAlchemy 2, Alembic, SQLite, httpx; фронт — Jinja2 + Alpine.js (без сборки).

## Безопасность

- Создавать и менять можно только кампании, чьё имя начинается с `CAMPAIGN_PREFIX`.
  Перед каждым изменяющим запросом backend заново читает кампанию из Keitaro и проверяет
  префикс; иначе — 403, запрос в Keitaro не уходит.
- Клиент Keitaro умеет менять только кампании и их потоки. Методов для изменения офферов,
  доменов, групп и источников нет.
- Каждый изменяющий запрос к Keitaro пишется в таблицу `operation_log`.
- URL и API-ключ — только в `.env`; в ответы и логи они не попадают.

## Установка

Нужен Python 3.12+.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt        # для тестов: requirements-dev.txt
cp .env.example .env                              # и заполнить
```

## Настройки (`.env`)

| Переменная | Описание |
|---|---|
| `KEITARO_API_URL` | Адрес Admin API **вместе с** `/admin_api/v1` |
| `KEITARO_API_KEY` | API-ключ: в админке Keitaro → Профиль → API ключи |
| `KEITARO_TIMEOUT` | Таймаут запросов к Keitaro, секунды (по умолчанию 15) |
| `CAMPAIGN_PREFIX` | Префикс разрешённых кампаний, например `test_lastname_` |
| `KEITARO_DOMAIN` | Домен новых кампаний — **по имени**, например `example.com` |
| `KEITARO_GROUP` | Группа кампаний — по имени |
| `KEITARO_SOURCE` | Источник трафика — по имени |
| `DATABASE_URL` | База обёртки, по умолчанию `sqlite:///./app.db` |

ID домена, группы и источника приложение получает через API по имени (кэш 10 минут).
Проверить настройки: `GET /api/reference` — если имя не найдено, ответ скажет, какое именно.

## Миграции

```bash
.venv/bin/alembic upgrade head
```

Адрес базы Alembic берёт из `DATABASE_URL`. Новая миграция после изменения `app/models.py`:
`.venv/bin/alembic revision --autogenerate -m "описание"`.

## Запуск

```bash
.venv/bin/uvicorn app.main:app --reload
```

Открыть http://127.0.0.1:8000 — создание кампании, http://127.0.0.1:8000/editor — редактор.
Документация API: http://127.0.0.1:8000/docs.

## Тесты

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest
```

Keitaro в тестах заменён на поддельный (`tests/fake_keitaro.py`, через respx); любой запрос
к настоящему серверу роняет тест. Тесты используют свои переменные окружения и временную
базу — `.env` и `app.db` не читаются.

## Как работает редактор

- **Доли** — целые числа, сумма активных офферов 100%. При добавлении, удалении и возврате
  оффера: закреплённые (pin) доли сохраняются, остаток делится поровну между остальными,
  а остаток от деления — по +1 последним офферам: 3 оффера → 33/33/34, 7 → 14×5 + 15×2.
  Удалённые — 0%.
- **Черновик**: изменения подсвечивают поток жёлтым и хранятся только в браузере до
  Push to KT или Cancel. Pin сохраняется сразу (в Keitaro его нет).
- **Fetch streams from KT** перечитывает потоки. Оффер, удалённый прямо в админке Keitaro,
  показывается как удалённый (0%), а доли остальных не пересчитываются до следующего
  действия — так видно, что сумма уже не 100%.
- **Одновременные правки**: если поток изменили в Keitaro после загрузки, Push отвечает 409
  и просит перечитать потоки.
- В БД (`stream_offer`) хранится то, чего нет в Keitaro: удалённые офферы, pin и имена
  офферов. Кампании и потоки не хранятся — источник правды Keitaro.

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/reference` | Домен, группа, источник из `.env` с ID |
| GET | `/api/offers?q=` | Поиск офферов по началу ID или части имени (до 20) |
| GET | `/api/campaigns` | Кампании с префиксом |
| POST | `/api/campaigns` | `{name, geo, offer_id}` → кампания + Flow 1 + Flow 2 |
| GET | `/api/campaigns/{id}/streams` | Потоки кампании, синхронизация со снимком |
| POST | `/api/shares/rebalance` | Пересчёт долей черновика (без сохранения) |
| PATCH | `/api/streams/{id}/offers/{offer_id}` | `{pinned}` — закрепить долю |
| PUT | `/api/streams/{id}/offers` | `{base, offers}` — опубликовать черновик в Keitaro |

Ошибки: `{"error": "...", "detail": "...", "keitaro_status": ...}`. 403 — чужая кампания,
404 — нет в Keitaro, 409 — конфликт, 422 — неверные данные, 502 — ошибка Keitaro,
504 — Keitaro не ответил.

## Особенности Keitaro API

- `POST /campaigns` требует `alias`, хотя в документации написано, что он генерируется —
  приложение генерирует его само (8 символов `a-z0-9`).
- `PUT /streams/{id}` с полем `offers` заменяет массив офферов целиком.
- Права ключа могут ограничивать видимые офферы: `GET /offers` возвращает только доступные,
  а на чужой оффер — 403. Такие офферы в редакторе показываются как «Offer #id».
- Поиска по офферам в API нет: список кэшируется на 5 минут и фильтруется в приложении.
