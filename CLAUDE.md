# Keitaro API (установлено на этапе исследования)
- `KEITARO_API_URL` уже включает `/admin_api/v1` — пути добавлять как `/campaigns`, не дублировать префикс.
- Авторизация: заголовок `Api-Key`.
- Права ключа ограничены (ACL): видно 1 оффер, 1 домен, 1 источник; `GET /offers/{id}` на чужой оффер → 403. Оффер без доступа показывать как «Offer #id».
- Поле `token` в ответе кампании — ключ Click API, считать секретом, не логировать.
- `POST /campaigns` без `alias` → 422 `{"alias":["Alias is required"]}` (вопреки описанию в спеке) — генерируем сами. Ошибки валидации Keitaro приходят в виде `{"поле": ["сообщение"]}`.
- `GET /offers` без поиска и пагинации — автокомплит фильтрует полный список на нашей стороне.
- Офферы потока меняются только через `PUT /streams/{id}` с массивом `offers:[{offer_id, share, state}]`, отдельного эндпоинта нет. Проверено на 216608:
  - переданный `offers` **заменяет массив целиком** (отсутствующие удаляются);
  - у оставшегося `offer_id` сохраняется `id` строки, у заново добавленного он новый;
  - PUT без ключа `offers` не трогает офферы (частичное обновление);
  - Keitaro принимает доли с суммой ≠ 100 (например, 60) — сумму 100 проверяем сами.
- Целевая схема кампании: `type:"position"`; Flow 1 — `schema:"redirect"`, `action_type:"http"`, `action_payload:"https://google.com"`, фильтр `{"name":"country","mode":"accept","payload":["AU"]}`; Flow 2 — `schema:"landings"`, `action_type:"http"`, `offers:[...]`.
- Справочники: домен `kylovoa.com` = 1813, группа кампаний `FORTESTS` = 10332, источник `FORTESTS` = 836. В конфиге задаются по имени, ID получаем через API.
- Моя тестовая кампания: `test_akella_campaign1`, id 216608 (домен 1813, группа 10332, источник 836); Flow 1 = 1332100 (AU → google), Flow 2 = 1332101 (оффер 18813, 100%).

# Доли офферов (решения)
- Пересчёт при add / remove / bring back; при fetch пересчёта нет.
- `free = 100 − Σ доли закреплённых (pin) активных`; `n` — активные без pin; каждому `free // n`; остаток `r` — по +1 последним `r` офферам (порядок Keitaro). Removed → 0%.
- Сортировка в таблице: по убыванию доли, при равенстве — порядок Keitaro; removed внизу.
- Removed и pin хранятся в БД обёртки; draft (жёлтое состояние) — только на фронте.
- Колонки таблицы: только Share и Actions.
